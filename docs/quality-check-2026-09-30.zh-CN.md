# 现有功能质量检查

日期：2026-09-30。

本轮覆盖全仓库静态检查、现有 JavaScript 测试、Django 单元/契约/冒烟测试、生产构建检查及部分浏览器页面。不是所有功能、角色和浏览器组合的穷举验收。

## 已修复

| 问题                                       | 根因与修复                                                                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 新建项目失败，错误提示却是项目重名         | 中文默认状态把 backlog 和 unstarted 都命名为“待办”，违反项目内状态名唯一约束。unstarted 改为“未开始”，增加默认状态唯一性测试。 |
| 项目创建中途失败可能留下半成品             | 应用端项目创建未使用事务。增加原子事务，工作流状态创建失败时回滚项目、成员及用户偏好。                                         |
| 消息队列不可用可能导致创建成功却返回错误   | 应用端活动任务改为事务提交后执行，使用 robust 回调隔离队列异常。                                                               |
| 无关唯一约束错误被误报为项目重名           | 外部 API 不再匹配异常文本中的 `already exists`，改为识别具体的项目名称/标识唯一约束。                                          |
| 关闭偏好、清空筛选后旧值残留               | 存储工具错误丢弃 `false`、空字符串和空对象/数组。现在保留这些有效值。                                                          |
| 禁用浏览器存储、配额耗尽或坏 JSON 导致异常 | 覆盖读写和清理时的异常；存储不可用时保留界面内存状态。Web 旧 Hook 统一复用共享实现。                                           |
| 首页“配置工作区”跳错地址                   | 相对链接 `settings` 改为包含工作区标识的绝对路径，并测试不同工作区。                                                           |
| 模块进度可能除以零                         | 重复检查完成数，遗漏总数。改为检查总数后计算百分比。                                                                           |
| 构建后格式检查反复失败及重复热更新         | 翻译类型生成器的分号换行不符合格式规范；同时避免内容不变时重写文件。                                                           |
| Admin/Space 的 Vite 路径插件兼容提示       | 使用 Vite 原生 `resolve.tsconfigPaths`，与 Web 配置一致。                                                                      |
| API 测试随机出现 429                       | API Key 的限流历史在用例之间共享。测试缓存改为进程内缓存并逐用例清理，真实限流逻辑仍启用。                                     |
| 测试复用旧表结构产生大批假失败             | 完整 Docker 测试默认添加 `--create-db`，文档说明切换分支及模型变更后的重建要求。                                               |
| `apps/api/run_tests.sh` 无法启动           | 脚本指向不存在的文件。改为调用相邻 Python 入口，并固定测试工作目录和解释器。                                                   |

## 复测命令

在仓库根目录运行：

```bash
pnpm turbo run check:types check:format check:lint --force
pnpm turbo run test
pnpm turbo run build --filter=web --filter=admin --filter=space --filter=live --concurrency=2
docker compose -f docker-compose-test.yml run --rm api-tests \
  pytest -o addopts='--strict-markers --create-db --nomigrations -q'
```

`--create-db` 只针对隔离测试数据库；不要将测试环境变量改为开发或生产数据库地址。
